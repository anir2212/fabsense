# Data provenance

The photo-bay, MSA and facilities modules use **only generated data**. `fabstack.sim_photo`, `fabstack.msa`, and `fabstack.utilities` contain their assumptions and seeds; generated CSV/JSON/DuckDB outputs live under ignored `runs/`. These inputs are not empirical fab or facilities measurements.

## UCI SECOM yield baseline, added 18 October 2026

- **Authoritative source:** [UCI Machine Learning Repository, SECOM dataset 179](https://archive.ics.uci.edu/dataset/179/secom), donated by Michael McCann and Adrian Johnston. Citation: McCann, M. & Johnston, A. (2008). *SECOM* [Dataset]. UCI Machine Learning Repository. https://doi.org/10.24432/C54305.
- **Archive URL:** `https://archive.ics.uci.edu/static/public/179/secom.zip`; downloaded on 2026-10-18. SHA-256: `eea568baf3c2229096d7d294cf0b096b5502bd96d92c0b80a65b84714059be8e`. The downloader verifies this hash before accepting the archive. Raw files stay in ignored `data/raw/` and are not published in the project repo.
- **License:** CC BY 4.0, as stated on UCI's dataset page; credit appears here and in the result record.
- **Grain and labels:** 1,567 records, 590 numeric sensor columns in `secom.data`, and one `secom_labels.data` line per record. UCI defines `-1` as pass and `1` as in-house test fail. The label file also has a timestamp. The code sorts by that timestamp and excludes it from predictors.
- **Split and limitation:** First 80% by timestamp for development, last 20% for a single held-out check. Five stratified folds within development fit missingness selection, imputation and variance screening afresh. The timestamp is the test point's recorded time, not proof of prospective deployment. Sensor IDs have no physical meanings here; model attribution is not causal yield diagnosis.

## NASA C-MAPSS remaining-life data: FD001 added 19 October 2026, FD003 added 23 October 2026

- **Authoritative source:** [NASA Prognostics Center of Excellence data repository, Turbofan Engine Degradation Simulation](https://www.nasa.gov/intelligent-systems-division/discovery-and-systems-health/pcoe/pcoe-data-set-repository/). Dataset citation supplied there: Saxena, A. & Goebel, K. (2008), *Turbofan Engine Degradation Simulation Data Set*, NASA Prognostics Data Repository, NASA Ames Research Center.
- **Archive URL:** `https://phm-datasets.s3.amazonaws.com/NASA/6.+Turbofan+Engine+Degradation+Simulation+Data+Set.zip`; downloaded on 2026-10-19. Outer ZIP SHA-256: `c9c5dec12a945a82e8bb4446589d7fb3cc057b5e5d81fa1a12e25ee9912ad3b2`. `fabstack.cmapss.ensure_archive` checks the hash on download and reuse. Its nested `CMAPSSData.zip` contains train/test/RUL text files for four subsets, FD001 to FD004, plus NASA's readme and a paper. FD001 and, since 23 October 2026, FD003 are read; FD002 and FD004 have not been loaded. Raw bytes stay in ignored `data/raw/` and are not republished.
- **Rights:** The inspected NASA repository page provides a public download and requested citation but no explicit per-dataset redistribution license. This repo publishes code and aggregate evidence only. The separate C-MAPSS simulator software availability notice is not a license for this dataset.
- **What the rows mean:** C-MAPSS is **simulated turbofan** degradation, not measurements from a fab or an aircraft fleet. FD001 has one operating condition and one fault mode. `train_FD001.txt` has 20,631 cycle rows from 100 run-to-failure engines. `test_FD001.txt` has 13,096 observed cycle rows from 100 different, truncated engines. `RUL_FD001.txt` gives the true number of cycles after each test engine's last observed row, in engine-ID order. Each cycle row has engine ID, cycle, three settings and 21 sensor values.
- **Split and leakage rule:** A seeded 80/20 engine split of the training engines selects among fixed models using four causal pseudo-endpoints per held-out engine. Rolling features only use the current and earlier cycles of the same engine. Once selected, a model is refitted on all 100 training engines and evaluated once at the last observed cycle of each official test engine. Training labels are capped at 125 cycles; official test labels remain uncapped for RMSE and the asymmetric score. This is one simulated-source benchmark without a physical failure-onset label or external fleet validation.
- **FD003, added 23 October 2026 as an untouched held-out test.** Same archive and hash, no new download. FD003 has one operating condition like FD001 but two fault modes (HPC and fan degradation), so it is a shifted test, not a second FD001 sample. `train_FD003.txt` has 24,720 cycle rows from 100 run-to-failure engines and `test_FD003.txt` has 16,596 observed rows from 100 truncated engines; `RUL_FD003.txt` gives 100 true remaining-cycle labels in engine-ID order. `fabstack.cmapss.load_subset("FD003")` applies the same shape, engine-ID, cycle-order and label checks as FD001. Under the protocol in [docs/NEURAL_RUL_PROTOCOL.md](../docs/NEURAL_RUL_PROTOCOL.md), models are fitted on FD001 training engines only; FD003 training rows are loaded for the checks and not used, and each FD003 test engine is scored once at its last cycle. The FD003 test labels are no longer untouched after that run. FD002 and FD004 (six operating conditions) remain unread.

The original plan also mentions WM-811K wafer maps and building energy data such as BDG2. Those have not been downloaded, licensed, cleaned, split or benchmarked in this repository. Before adding another source, document its authoritative landing page, version/checksum, license, download date, label definition, entity/time split, leakage controls and intended use. No real-data metric is claimed for those modules.
